# Agent instructions: BQ Design Critic

Read `skills/design-critic/SKILL.md` before performing any design critique or redesign. Read `rubric.json` for the current scoring criteria and severity model.

- Do not start modifying components until an evidence-backed critique exists, unless user explicitly requests a direct edit.
- Use screenshots, live app inspection, and/or actual code as evidence. Do not claim a viewport was tested unless it was.
- Respect each project's existing brand tokens, copy, assets, and accessibility requirements.
- Avoid fabricated screenshots, metrics, testimonials, logos, prices, and personal data.
- Treat existing designs as baseline; prefer targeted, reversible improvements to wholesale restyling.
- Motion must serve interaction or storytelling, remain performant, and support reduced-motion preferences.
- Never reference private employer systems or copy third-party design content.

For inspiration-led explorations, read `inspiration/README.md` and the linked 76-study source index. Credit creators and translate mechanisms into original product designs; do not copy their source, screenshots or branded assets. Keep critique findings independent from taste references.
